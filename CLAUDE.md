# Claude.md

Инструкции для Claude Code по проекту «Замер скорости интернета».

## Контекст задачи

Тестовое задание: консольный скрипт для замера скорости скачивания.

**Требования:**
- Язык: Python **или** Node.js (выбрать один, обосновать в README)
- Принимает URL (например, тяжёлую картинку) — можно через аргумент CLI или интерактивный ввод
- Делает **10 последовательных** запросов, дожидаясь **полного** ответа на каждый
- Считает:
  - среднее время одного запроса
  - общий объём скачанных данных
  - скорость скачивания
- Печатает результат в консоль
- Единицы измерения — на выбор разработчика, **обязательно** указать в README
- Залить на GitHub, добавить README с инструкцией по запуску

**Ориентир по времени:** 1–2 часа. Не переусложнять.

## Рекомендации по реализации

### Выбор стека
Предпочтительно **Python 3.10+** — минимальные зависимости, читаемый код, стандартная библиотека покрывает всё необходимое. Node.js допустим, если есть веская причина.

### Структура проекта (Python)
```
.
├── README.md
├── speedtest.py          # основной скрипт (один файл, без пакетов)
├── requirements.txt      # только если реально нужны сторонние либы
└── .gitignore
```

Один исполняемый файл предпочтительнее разбиения на модули — задача маленькая.

### Алгоритм
1. Распарсить URL из `sys.argv` (или `argparse`). Валидировать схему (`http`/`https`).
2. Цикл `range(10)`:
   - замерить `time.perf_counter()` до и после
   - выполнить `requests.get(url, stream=True)` (или `urllib` для zero-dependency)
   - прочитать тело **полностью** (`resp.content` или `b"".join(resp.iter_content(...))`) — важно, чтобы замер отражал реальное скачивание, а не только заголовки
   - накопить `len(body)` и длительность
3. Агрегация:
   - `total_bytes = sum(sizes)`
   - `avg_time = sum(durations) / len(durations)`
   - `speed = total_bytes / sum(durations)` → перевести в удобные единицы
4. Вывод в консоль: среднее время (сек или мс), суммарный объём (МБ), скорость (Мбит/с и/или МБ/с).

### Детали, которые легко упустить
- **Полный ответ:** не забыть прочитать тело, иначе скорость будет завышена в разы.
- **Таймауты:** поставить `timeout=30`, чтобы скрипт не зависал на «битом» URL.
- **Ошибки:** ловить `requests.RequestException` / `URLError`, выводить понятное сообщение и `exit(1)`. Не ронять трассировкой.
- **Единицы:** явно указать в выводе и в README — например, «Мбит/с (мегабиты в секунду)» и «МБ (мегабайты)». Не путать биты/байты (`bytes * 8 / seconds / 1e6` для Мбит/с).
- **Прогрев:** первый запрос может быть медленнее (DNS, TLS handshake). Допустимо: либо явно упомянуть это в README, либо сделать один «прогревочный» запрос. Не обязательно, но стоит зафиксировать решение в README.
- **Прогресс:** печатать `#1 ... 200 OK, 1.2 MB, 0.85s` по ходу — приятно и понятно при отладке.

## Чего не делать

- Не добавлять многопоточность/асинхронщину — задача требует **последовательных** запросов.
- Не прикручивать GUI, конфиги, логирование в файлы, Docker — избыточно для тестового.
- Не тянуть тяжёлые зависимости (например, `speedtest-cli`) — задача про «свой» замер.
- Не забывать про `.gitignore` (виртуальное окружение, `__pycache__`, `.idea/`).
- Не коммитить сгенерированные файлы и секреты.

## Definition of Done

- [ ] Скрипт запускается одной командой и отрабатывает на публичном URL
- [ ] Ровно 10 последовательных запросов, тело каждого читается полностью
- [ ] В консоль выводится: среднее время, суммарный объём, скорость — с единицами
- [ ] Ошибки обрабатываются без трейсбеков
- [ ] README содержит инструкцию и раздел про единицы
- [ ] Репозиторий на GitHub публичный, коммиты осмысленные (1–3 штуки достаточно)
- [ ] Ветка `main` актуальна

## Стиль кода

- Понятные имена (`total_bytes`, `avg_seconds`, `mbps`), без «магии» в числах
- Короткие функции: `fetch_once(url) -> tuple[bytes_len, seconds]`, `main()`
- Минимум комментариев — только там, где неочевидно (например, конвертация бит/байт)
