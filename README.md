# Замер скорости интернета

Консольный скрипт, который скачивает файл по URL (например, тяжёлую картинку) **10 раз подряд**, каждый раз дожидаясь полного ответа. Затем печатает среднее время одного запроса, общий объём скачанных данных и скорость скачивания.

## Почему Python

Выбран Python: стандартная библиотека (`urllib`, `time.perf_counter`, `argparse`) закрывает всю задачу. Сторонних зависимостей нет, весь код лежит в одном файле. Node.js здесь ничего бы не добавил, а асинхронная модель для **последовательных** запросов не нужна.

## Требования

- Python **3.10+** (проверено на 3.13)
- Сторонних зависимостей нет, поэтому `requirements.txt` отсутствует

## Установка

```bash
git clone https://github.com/Seraph325/internet-speed-test.git
cd internet-speed-test
```

Больше ничего ставить не нужно.

## Запуск

```bash
python speedtest.py https://images.unsplash.com/photo-1506744038136-46273834b3fb
```

Если URL не указан, скрипт спросит его интерактивно:

```bash
python speedtest.py
Введите URL: https://...
```

Опции:

| Флаг | Описание |
|---|---|
| `--timeout N` | таймаут сетевых операций в секундах (по умолчанию 30) |
| `--no-warmup` | не делать прогревочный запрос перед замером |
| `-h`, `--help` | справка |

## Единицы измерения

| Величина | Единица | Определение |
|---|---|---|
| Время запроса | **с** (секунды) | от отправки запроса до получения последнего байта тела |
| Объём | **МБ** (мегабайты, десятичные) | 1 МБ = 1 000 000 байт; точное число байт печатается рядом |
| Объём меньше 1 МБ | **КБ** (килобайты, десятичные) | 1 КБ = 1 000 байт; применяется автоматически |
| Скорость | **Мбит/с** (мегабиты в секунду) | `байты × 8 / секунды / 1 000 000` |
| Скорость (доп.) | **МБ/с** (мегабайты в секунду) | `байты / секунды / 1 000 000` |

Используются десятичные приставки (10⁶), как у провайдеров и в популярных спидтестах, а не двоичные МиБ (2²⁰).

Формулы:

- среднее время = сумма длительностей / 10
- общий объём = сумма размеров тел всех 10 ответов
- скорость = общий объём / суммарное время 10 запросов

## Замечания и ограничения

- **Прогревочный запрос.** Первый запрос обычно медленнее остальных: холодный DNS-кэш, «прогрев» кэша CDN. Поэтому перед замером скрипт делает один дополнительный запрос. Он печатается, но в статистику не входит. В статистику идут **ровно 10** запросов. Отключается флагом `--no-warmup`.
- **Новое соединение на каждый запрос.** `urllib` не держит keep-alive, поэтому каждый из 10 запросов заново устанавливает TCP- и TLS-соединение. Эти накладные расходы входят в замер. На маленьких файлах они заметно занижают скорость, поэтому лучше брать файл от нескольких мегабайт.
- **Тело читается полностью**, блоками по 64 КБ. Время останавливается только после последнего байта, поэтому скорость не завышается.
- **Сжатие.** Скрипт не запрашивает gzip, поэтому считается объём тела ответа в том виде, в каком его отдал сервер.
- **Таймаут** 30 с по умолчанию. Он ограничивает установку соединения и ожидание каждого блока данных, а не всё скачивание целиком.
- **Ошибки** (неверный URL, DNS, HTTP 4xx/5xx, таймаут, обрыв соединения) выводятся одной строкой без трейсбека. Коды выхода: `1` при сетевой или HTTP-ошибке, `2` при неверных аргументах, `130` при прерывании через Ctrl+C.
- **Что не учитывается:** скорость отдачи (upload), пинг и джиттер, параллельные потоки. Результат зависит от сервера, на котором лежит файл, и от CDN, а не только от вашего канала. Некоторые хостинги (например, Wikimedia) могут ответить 429 на частые запросы.
